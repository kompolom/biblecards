# Feature Sliced Design (FSD) Expert

Этот skill помогает проектировать фронтенд-архитектуру по методологии **Feature-Sliced Design**.

## Основные концепции

FSD — это методология проектирования фронтенд-приложений, которая разбивает проект на слои, слайсы и сегменты.

### 1. Слои (Layers)
Верхний уровень иерархии. Модули на верхних слоях могут импортировать код только из нижних слоев.
- `app` — инициализация приложения (провайдеры, роутинг, глобальные стили).
- `pages` — страницы приложения.
- `widgets` — самостоятельные блоки страниц (например, Navbar, Footer, UserCardList).
- `features` — части функционала, несущие бизнес-ценность (например, `AddToCart`, `ChangePassword`).
- `entities` — бизнес-сущности (например, `User`, `Product`, `Order`).
- `shared` — переиспользуемый инфраструктурный код (UI-kit, API-клиенты, хелперы).

### 2. Слайсы (Slices)
Разделение кода по предметной области (домену) внутри слоев `pages`, `widgets`, `features`, `entities`. 
*Важно:* Слайсы одного слоя не могут импортировать друг друга.

### 3. Сегменты (Segments)
Разделение внутри слайсов по техническому назначению:
- `ui` — компоненты и стили.
- `model` — бизнес-логика, хранилища (store), типы.
- `api` — запросы к бэкенду.
- `lib` — вспомогательные функции.
- `config` — конфигурационные данные.

## Ключевые правила

1. **Направленность зависимостей**: Импорт возможен только из слоев, находящихся ниже в иерархии (`shared` < `entities` < `features` < `widgets` < `pages` < `app`).
2. **Public API**: Каждый слайс и сегмент должен иметь `index.ts` файл, который является единственной точкой входа. Запрещены глубокие импорты (например, `import { ... } from '@/entities/user/ui/UserCard'`). Правильно: `import { ... } from '@/entities/user'`.
3. **Изоляция слайсов**: Слайсы на одном слое должны быть максимально независимы друг от друга.

## Проектирование Public API

Public API — это «контракт» слайса, определяющий, что доступно внешнему миру.

### 1. Единая точка входа
- Каждый слайс (`entities/user`, `features/auth`) должен иметь `index.ts`.
- **Запрещено**: Импортировать файлы слайса напрямую (например, `from '@/entities/user/ui/Card'`).
- **Разрешено**: Только через Public API (`from '@/entities/user'`).

### 2. Состав Public API
- Экспортируйте только то, что действительно необходимо другим модулям.
- Избегайте `export * from '...'` (wildcard exports). Это ухудшает навигацию и может привести к случайному экспорту внутренних деталей.
- Явно перечисляйте экспорты: `export { UserCard } from './ui/UserCard'`.

### 3. Решение проблемы Cross-imports (слой Entities)
Перекрестные импорты между слайсами одного слоя запрещены везде, кроме `entities`. Если `Entity B` зависит от `Entity A`:
1. Создайте в `entities/A` папку `@x`.
2. Внутри создайте файл с именем зависимого слайса: `entities/A/@x/B.ts`.
3. В этом файле экспортируйте только то, что нужно для `Entity B`.
4. В `entities/B` импортируйте через этот файл: `import { ... } from '@/entities/A/@x/B'`.

### 4. Особенности слоя Shared
- Для `shared/ui` и `shared/lib` рекомендуется использовать **индивидуальные Public API** для каждого компонента/утилиты.
- Это предотвращает раздувание бандла и проблемы с tree-shaking.
- Пример: `import { Button } from '@/shared/ui/button'` вместо одного гигантского `shared/ui/index.ts`.

### 5. Предотвращение циклических зависимостей
- **Никогда** не импортируйте из `index.ts` (собственного Public API) внутри того же слайса.
- Если компоненту `A` внутри слайса нужен компонент `B` из этого же слайса, используйте относительный импорт напрямую к файлу или сегменту.

## Как использовать этот skill для планирования

1. **Определите сущность (Entity)**: Какие данные являются ключевыми? (User, Task, Project).
2. **Определите фичи (Features)**: Какие действия пользователь совершает с этими данными? (Создание задачи, удаление проекта).
3. **Соберите виджеты (Widgets)**: Какие блоки объединяют фичи и сущности для удобного отображения на странице?
4. **Разместите на страницах (Pages)**: Скомпонуйте виджеты и фичи в конечные маршруты.
5. **Вынесите общее в Shared**: Базовые UI-компоненты, типы API, утилиты.
